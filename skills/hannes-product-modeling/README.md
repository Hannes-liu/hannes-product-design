# hannes-product-modeling

一个独立的产品业务建模 Skill，用于理解业务对象、参与者、权限、状态、动作和数据之间的关系，形成业务模型、规则规格、变更分析或一致性评审。

可以从一句业务描述或一个局部问题开始。已有模型、文档、界面和实现都可以作为证据；没有这些材料时，也能先分析已知规则。四种模式分别解决不同问题，可直接选用。

## 1. 直接使用

本 Skill 位于 `hannes-product-design/skills/hannes-product-modeling/`。保留完整目录，在对话中提供 `SKILL.md` 的完整路径即可使用，无需全局安装。下面是提示词示例，请替换为本机实际路径：

```text
请读取并使用：
/你的目录/hannes-product-design/skills/hannes-product-modeling/SKILL.md

我们在定义共享资源预约业务：
成员可以预约资源，管理员维护资源的开放时段；
同一资源同一时段不能被重复占用，预约可以取消或到期结束。

请梳理业务对象及关系、角色权限、状态与动作、关键约束。
未明确的规则列为待确认问题。本轮只在对话中分析。
```

Skill 根据本次问题确定范围。只有一条规则需要分析时，可以直接问：“预约取消后，哪些关联数据需要变化？”不必先补齐整份业务材料。

## 2. 四种模式

| 业务问题 | 模式 | 主要产出 |
| --- | --- | --- |
| 系统管理什么，谁负责，状态如何变化 | `model` | 对象关系、角色权限、状态动作、数据规则与未决事项 |
| 一项对象、动作或协作规则如何明确表达和验证 | `spec` | 业务含义、输入与条件、结果、异常和验证场景 |
| 新规则会影响哪些既有规则与关联对象 | `change` | 新旧差异、依赖与影响范围、规则补丁和验证要求 |
| 已有规则或材料是否冲突、遗漏或不可执行 | `review` | 问题、依据、影响、建议及验证限制 |

模式不要求按顺序使用。无需记忆模式名，直接描述业务问题也可以。

### model：建立业务模型

```text
使用 hannes-product-modeling 的 model 模式。

资源可被不同成员预约，每个预约关联一个资源和一段时间。
管理员可以暂停资源使用，但暂停是否影响已有预约尚未确定。

请分析对象关系、责任归属、状态与动作，
区分资源状态与预约状态，并列出需要确认的规则。
仅分析当前范围，不设计页面或修改文件。
```

### spec：明确一项业务动作

```text
使用 hannes-product-modeling 的 spec 模式。

已确认：成员只能取消自己的预约；
仅待开始的预约可取消，开始时间到达后不可取消；
取消后释放对应占用，重复取消不能重复释放。

请将“取消预约”写成业务规格：
对象与角色、输入、权限、前置条件、成功结果、
失败与重复处理、验证场景及待确认规则。
本轮直接在对话中给出规格。
```

### change：分析规则变化

```text
使用 hannes-product-modeling 的 change 模式。

原规则：资源暂停仅影响新的预约。
新规则：资源暂停还会使该资源尚未开始的预约失效。

请基于已有模型分析状态、权限、占用和关联记录受哪些影响，
区分新规则已经明确的内容与仍需确认的处理方式。
只输出差异、影响和验证要求，不修改文件。
```

### review：核对规则与事实

```text
使用 hannes-product-modeling 的 review 模式。

业务规定同一资源同一时段不可重复占用，取消预约后释放占用。
现有样例中，一条预约已取消但仍占用资源；
另外两条有效预约关联同一资源且时间重叠。

请检查规则和样例的一致性，列出问题、依据、影响和建议。
只读分析，未实际运行的部分标为待验证。
```

## 3. 分析范围与输入

可提供业务目标、自然语言描述、规则、访谈记录、表格、样例、已有模型或实现证据。已有 PRD 和原型也是可选证据。

建议说明：

- **问题范围**：整体业务、某类对象，还是一个状态或动作。
- **已知依据**：哪些规则已经确认，哪些存在变化或冲突。
- **输出形式**：对话分析，或保存、更新指定文件。

没有现有模型时，从当前已知业务开始；缺失的关键规则列为问题。已有模型时，复用其命名与依据，不因小改动重新建模全部业务。

## 4. 按需表达为页面规格

需要信息架构、交互或页面级 PRD 时，可将业务模型进一步表达为页面职责、显示与输入、数据来源、操作和判断逻辑。此时才加载 [页面规格](references/page-spec.md)。

```text
使用 hannes-product-modeling，基于已确认的预约规则，
整理预约列表与详情的页面规格，明确字段、数据范围、
可用动作、状态限制和失败反馈。
请判断哪些内容可以复用，输出到我指定的文档中。
```

页面的划分依据对象、用户任务和权限差异。对象模型、动作规格、状态机和规则评审也可以作为完整结果直接使用。

## 角色与流程表达

从主流程所需的实际参与者开始，仅按处理责任、决策权限或数据访问差异拆分并说明依据。同一角色可承担多个步骤；不根据岗位或阶段自动生成审批链。缺失责任列为问题，自动处理不默认增加人工岗位。

涉及 PRD 时，先说明核心任务、必要信息、决策、完成与恢复，再对应页面。新建或重构核心流程保留 Mermaid 图源，跨参与者移交用泳道表达；独立建模不要求界面，纯视觉调整不重画流程。具体规则见[模型契约](references/model-contract.md)与[页面规格](references/page-spec.md)。

## 5. 输出与保存

默认在对话中回答本次问题，不强制生成固定文件或整套模板。要求保存时，优先复用已有模型或用户指定文档；没有命名约定时，业务模型可使用 `product-model.md`。

每次结果说明采用的规则依据、尚未确定的问题和验证边界。规格中的预期行为、样例检查与实际运行验证分别记录。

业务分析成果保存在各自业务目录中，Skill 目录只维护通用方法和参考资料。

## 6. 可选安装

希望在多个项目中直接通过名称调用时，将整个目录安装到当前环境的 Skill 目录。Codex 默认使用 `$CODEX_HOME/skills`；未设置 `CODEX_HOME` 时通常为 `~/.codex/skills`。

安装后，在新会话中确认 Skill 已被发现，再使用：

```text
使用 $hannes-product-modeling，分析当前对象的状态和权限。
本轮只在对话中回答。
```

下载仓库不会自动全局安装。环境尚未发现该 Skill 时，继续使用完整路径，并保留 `references` 与 `agents`。

## 8. 维护与协作

本 Skill 在 `hannes-product-design` 仓库的 `skills/hannes-product-modeling/` 中维护，与 `hannes-requirement-to-design` 共用仓库根目录的 Git 与远程配置。提交和推送在仓库根目录执行，统一操作说明见根 README；单独取用本目录不影响本 Skill 的分析能力。

与设计 Skill 共同服务一个项目时，优先更新同一份现有项目规格。业务规则在其定义处维护，页面说明引用；由设计 Skill 维护协作项目的页面表达，本 Skill 补充业务约束和影响分析。独立接到页面规格任务时仍可直接完成，不另建与现有规格重复的版本。

安装或迁移前副本不作为另一套维护源。业务资料和生成成果保存在对应业务项目中。

## 跨会话继续与完整案例

按[项目续接](references/project-continuity.md)在现有说明中保留当前工作状态：依据、决定／问题、已完成范围、实际入口及验证与下一步。新会话先读该章节，只分析本次差异，不需要原始聊天。没有实现时明确说明，不强求页面或启动命令。

[预约业务案例](references/examples/reservation-model.md)提供虚构输入、模型、局部变更及验收预期，可独立复现业务分析；没有另一个 Skill 也能使用。
