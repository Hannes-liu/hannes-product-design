# 业务规格

把选定业务范围写成含义明确、可验证的规则。规格单元可以是对象、动作、对象间约束或多方协作，不要求存在界面或既有文档。只补充本次涉及的内容，已有规则可直接引用。

## 对象规格

说明业务含义、身份标识、参与角色、数据归属、关系与基数、生命周期及必须始终成立的约束。属性包含含义、取值范围、来源和变更条件；未明确的枚举、必填性或默认值列为待确认。

区分对象本身的事实与关联对象的状态，不把显示名称、页面分类或统计结果自动当作独立对象。

## 动作规格

| 内容 | 需要说明 |
| --- | --- |
| 目的与范围 | 谁对哪个对象执行什么业务动作 |
| 输入 | 用户提供、上下文提供或从已有对象读取哪些数据 |
| 权限 | 允许的参与者、归属范围、指派关系与例外依据 |
| 前置条件 | 允许的状态、时间、关联记录和所需版本 |
| 校验 | 必填、格式、范围、重复、跨字段与跨对象约束 |
| 成功结果 | 状态、关联数据、可用范围和下游读取发生哪些变化 |
| 失败与取消 | 哪个条件阻止动作、数据是否保持原状、如何表达原因 |
| 重复与并发 | 重试是否重复产生结果，冲突动作由什么规则决定 |

把“满足条件”“操作成功”展开为业务上可观察的判断与变化。动作成功所需的多项变化应保持一致；若允许中间状态或补偿，需明确依据与最终完成条件。具体技术机制仅在用户要求时讨论。

## 协作与跨对象约束

说明各参与方的责任、前后依赖、共享数据的来源及版本、完成条件和冲突处理。区分单条记录合法与多条记录组合合法；汇总规则写清空集合、部分完成和失败混合等边界。

不默认增加审批、撤回、解锁、通知或日志要求。只有当前业务涉及这些行为时才纳入规格。

## 验证场景

以“前提/输入 → 动作或事件 → 预期结果”关联规则。按范围覆盖正常、边界、越权、非法状态，以及有关的重复、并发和版本变化；未执行时标明待验证。

例如一项规则禁止在截止时间到达后修改记录，应分别说明截止前、恰好到达和截止后的预期。若时间来源或判定时点未确定，将其列为影响验证结论的待确认规则。

## 按需表达业务流程

用户要求业务流程时，说明核心任务、实际参与者、必要信息、关键决策、完成条件及相关取消、失败和恢复。流程中每个责任移交有业务依据；没有界面也可以表达事件和动作。

新建或重构核心流程并需要图示时，采用 Mermaid 流程图；跨参与者协作用 `flowchart` 分区表达泳道，只有真实自动处理才加入系统泳道。保留可编辑图源、标注分支条件并同步规则；渲染或运行验证未执行时明确说明。只分析局部规则时不强制补整张流程图。

## 页面表达

用户要求页面规格或页面级 PRD 时，再读取 [页面规格](page-spec.md)，将上述规则映射为显示、输入、交互与反馈。只要求业务规格时，直接输出对象或动作规则。

## 持续维护

复杂业务需后续继续时，在已有说明中按[项目续接](project-continuity.md)记录有效规则位置、决定、未决项、完成范围及验证与下一步，不复制另一份业务定义。新会话基于记录的版本分析本次差异。
