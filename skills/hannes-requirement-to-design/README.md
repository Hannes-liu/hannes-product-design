# hannes-requirement-to-design

面向 PC 和移动端产品界面的需求到设计 Skill。可以从文字需求、已有规格、截图或现有原型开始，按需补齐规格，交付可运行的 HTML 或项目页面及对应维护源码。重点是组件复用，以及规则、跨页数据和交互行为的一致性。

## 使用

未安装时，向支持读取本地文件的助手提供本目录 `SKILL.md` 的完整路径，并说明任务。安装后可用 `$hannes-requirement-to-design` 调用。

示例：

- 「使用这个 Skill，把事项协作需求做成 PC 和移动端原型，先让我选择设计模板。」
- 「根据已确认规格制作页面，沿用现有项目和视觉规范，直接完成关键流程。」
- 「根据这些截图还原移动页面，缺少原稿的部分标注为推导设计。」
- 「只调整现有详情页的返回行为，保留筛选与滚动位置，不改其他页面。」

[打开风格预览](assets/style-preview.html)，比较 Ant Design、TDesign 和参考 Apple HIG 的 Web 风格。这三套对比示例均为自制 HTML/CSS/JavaScript。

[打开真实组件库](assets/library.html)，查看 React 19.2.0、Ant Design 6.6.7 与 dayjs 1.11.13 的离线控件目录、受控业务组件和完整组合示例。此入口目前仅含 Ant Design；[复用与构建说明](references/component-library.md)介绍如何按需取源码和依赖，优先适配已有项目。

字体、行高、字间距、色彩、间距与组件尺寸见 [design-spec.md](design-spec.md)。预览新增设计参数面板，展示所选风格与视口的实际基线；页面与弹层使用同一组变量。

已有项目规范或已选风格时直接沿用。无基线时先选择模板，再制作目标页面；明确授权助手决定时不额外等待。

复杂业务可按需调用 `hannes-product-modeling`，没有该 Skill 也可继续分析和制作。两个 Skill 均可独立使用，也不绑定框架或设计工具。共同服务项目时更新同一份项目规格：建模明确业务规则，设计负责页面与交互表达，不另建一套重复页面规则。

## 范围、流程与设计说明

从已有参与者和核心任务收敛范围，按实际责任、决策权限和数据访问差异拆角色；不因岗位或流程阶段不同而增加角色。核心任务明确功能与内容、本次边界、优先级理由和验收预期。

新建或重构核心流程时，在 PRD 中表达任务、必要信息、决策、完成与相关恢复路径，并保留 Mermaid 流程图；跨参与者协作用泳道，图与页面对应。详见[需求与页面规格](references/requirements.md)。

[设计知识](references/design-knowledge.json)提供现有三套基线、通用页面／交互模式及质量约束，适用条件、反模式和来源可追溯。直接按关键词或 ID 查阅，不需要检索脚本或新增依赖；数值继续引用设计规范，不复制另一份参数表。

先按[任务与信息表达](references/task-representation.md)确定核心判断所需的视图，例如用资源时间轴比较空闲、用记录表格管理历史；不能用组件数量代替方案完整性。

按[设计决策与说明](references/design-decisions.md)记录页面和组件取舍。优先更新项目现有说明；未约定时在 `design/design-notes.md` 的同一文档维护全局基线、页面决策和明确局部覆盖。业务规则继续在 PRD 定义，知识建议不覆盖已确认项目规范。

示例调用：「依据当前预约规则，先围绕主流程梳理角色与用户任务，在 PRD 中画流程并对应页面；沿用项目设计体系，解释列表、详情和编辑的页面与组件选择，更新同一份项目设计说明。」

## 维护

本 Skill 在 `hannes-product-design` 仓库的 `skills/hannes-requirement-to-design/` 中维护；与建模 Skill 共用仓库根目录的 Git 和远程配置。整体定位、选择和提交方式见根 README，单独取用本目录仍可使用。入口是 [SKILL.md](SKILL.md)，详细规则在 `references/`，可离线打开的示例在 `assets/`。仅更新实际受影响的规则和示例，验证后再决定是否安装或发布。

本地整理不代表已安装 Skill、配置远程或上传。示例仅使用虚构数据；筛选、编辑与上传演示不接真实后端。组件库的 npm 依赖安装在 `assets/component-library/` 内，不是全局安装 Skill。

实际项目按任务记录检查结果与未验证范围；本包中的前端演示不代表真实系统集成或生产能力。
