# 验证与交付

## 依据任务确定验收

验收条件来自本次规格：用户要获得什么结果、哪些规则须成立、失败或取消后保留什么。按“任务／规则 → 页面与动作 → 预期结果 → 实际证据或待验证”核对；同时关注入口能否找到、必要信息是否充分、演示假设是否明确以及变更影响是否同步。

实现前先写出与控件名称无关的核心决策任务，检查初始页面是否提供足够信息。例如查空闲须能比较资源和完整时间、识别占用与未开放，再进入预约；不能只验证“新建按钮能提交”。结合[任务与信息表达](task-representation.md)保留至少一个不满足条件的反例与恢复路径。

优先使用当前环境已有的预览、浏览器操作与测试能力，不固定工具名称，也不另建一套平台执行流程。根据任务采用可用证据；静态审阅、任务走查、真实运行和用户测试分别记录，操作成功不等于真实用户可用性已验证。没有工具时保留验收预期并说明未实测部分。

## 按本次范围检查

| 检查对象 | 有意义的证据 |
| --- | --- |
| 规格覆盖 | 核心任务、必要功能与内容能对应到页面、关键字段、动作和状态；需求／演示假设有依据 |
| 任务与设计 | 任务入口、必要信息、分支与恢复和完成结果可走查；流程图与页面一致；局部设计覆盖有明确范围 |
| 业务交互 | 实际执行关键路径，检查对象与跨页数据更新，而非只看按钮存在 |
| 导航返回 | 菜单、直接路由、无效对象、回退、筛选/滚动恢复符合当前约定 |
| 权限与状态 | 角色/数据范围/状态对页面、字段和动作的影响，分清模拟与真实校验 |
| 组件控件 | 实际包与版本对应；搜索／清空／校验／加载反馈可用，键盘操作、受控回显、浮层挂载与关闭正常 |
| 布局与视觉 | 目标视口截图、溢出/遮挡检查；表格、图表和弹层可用 |
| 运行与分享 | 实际打开或启动，控制台/资源错误检查；分享包按约定方式打开；组件运行时、样式和按需资源包含在离线包内，按任务要求检查运行时网络请求 |

纯视觉修改无需重跑无关的完整业务；新变化或失败揭示影响时再扩大检查。截图用于核对视觉与布局，不能替代数据和交互验证。

浏览器工具可用时实际预览，使用稳定的界面语义和业务结果验证；有必要时保存截图或可复现步骤。工具不可用时完成静态检查，明确哪些交互与视口尚未实测，不能用“代码看起来正确”声称通过。

## 内置组件库维护

[真实组件目录](../assets/library.html)由 [组件库源码](../assets/component-library/)构建，与[三风格原生预览](../assets/style-preview.html)分别验证。维护源、版本及 npm 命令见[组件库与复用](component-library.md)。在源码目录运行构建与验证后，检查生成单文件能通过 `file://` 打开、运行时无外部请求，关键操作确实更新状态；保留适用生产依赖的许可声明。首次 npm 安装可能需要联网，不能据此把离线运行能力说成离线构建能力。

记录实际执行的命令、浏览器、视口、关键路径及限制，不把构建成功当作所有控件、浏览器、无障碍能力或生产业务已验证。工具包内部测试、评估和验证资料只保存在已忽略的本地目录，不随 Skill 分发；业务项目的验证结果保存在该项目约定位置，不写入 Skill 包。

## 交付说明

简要说明：

- 改了什么、完成哪些流程、采用什么设计基线。
- 可运行页面／预览入口、维护源码及实际运行方式；维护源与分享包的关系。
- 实际复用的组件及版本、接入位置与数据契约；关键页面间的数据、状态及返回行为是否一致。
- 哪些数据、角色、接口是模拟，是否存在持久化。
- 实际检查结果、待确认规则与未验证范围。
- 实际复用第三方内容时，附对应来源、版本和必要版权/许可声明；生成单文件或分享包时检查声明是否随产物保留，参考[来源与许可记录](../THIRD_PARTY_NOTICES.md)。

优先更新已有说明，小修改可在对话中交付，不强制新增文档。产物保存在目标项目，不打包真实资料、截图或聊天进 Skill。

## 交付后继续

对预计继续迭代的项目，按[项目续接](project-continuity.md)在现有说明中记录已完成范围、实际维护与预览入口、验证版本及下一步。源码、分享包、临时服务和内存数据分别说明；未验证或过期检查不能变成当前版本通过结论。纯讨论或很小修改无需强制生成交接文件。
