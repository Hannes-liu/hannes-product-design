# 设计基线与模板选择

## 如何选择

1. 用户明确指定设计体系或现有项目有已确认规范：沿用，并指出局部差异；不要求重新选模板。
2. 本次没有视觉依据：展示[可离线预览页](../assets/style-preview.html)及下表，等待用户选择；期间可继续分析业务与范围。
3. 用户明确授权自行决定：按产品类型和平台选一套，说明依据后推进。历史已确认选择持续有效。

| 模板 | 适用倾向 | 需要注意 | 详细规范 |
| --- | --- | --- | --- |
| Ant Design | 数据管理、表格与表单密集的桌面产品 | 移动端需重新组织内容，不能压缩桌面表格 | [Ant Design](styles/ant-design.md) |
| TDesign | 企业协作、统一组件体系的产品界面 | 桌面与移动组件体系有差异，按实际依赖适配 | [TDesign](styles/tdesign.md) |
| Apple Design | 强调内容层级与直接操作的 Web 产品 | 参考 HIG 的 Web 风格，不能声称原生平台能力 | [Apple Design](styles/apple-design.md) |

这些是可选择的起点，不是给产品贴标签。选定后记录模板、平台、来源/版本、局部覆盖与确认状态。使用时只读取对应模板；不要求每个阶段重复读取全部规范。

## 场景与设计决策

需要解释页面、组件或布局取舍时，读取[设计决策与说明](design-decisions.md)，再按本次任务查[结构化知识](design-knowledge.json)的相关记录与来源。目标端、项目约束优先，任务和密度决定表达；产品类型不直接决定主题色。无匹配时说明缺口，不把推导建议称为知识库结论。

项目说明优先沿用已有文档；无约定时在 `design/design-notes.md` 的同一文档中维护全局基线、页面决策和明确的局部覆盖。业务规则在 PRD 定义，不能通过设计覆盖更改权限、状态或流程。

## 参数规范

选定风格后，读取 [design-spec.md](../design-spec.md) 的共同规则及对应章节，应用已核实的字体、间距、色彩和布局基线。只需读取所选体系；页面骨架仍由任务决定。预览参数面板与实际 CSS 变量同步，修改模板时同步规范与示例。

## 模板与项目实现

- [三风格预览](../assets/style-preview.html)是自制 HTML/CSS/JavaScript，示范层级、结构和反馈；[真实组件目录](../assets/library.html)另用 React／Ant Design 构建，目前仅含 Ant Design，不能将其当作三套体系的通用运行时。
- 真实项目已经使用对应组件库时，复用其版本、组件 API 和主题能力；需要新增依赖时先检查目标任务与项目约束，不自动换框架。
- 没有组件库的 HTML 原型可按模板实现，但要说明近似范围。不能把模板里的 CSS 类名当作官方组件 API。
- 不混用三套体系的导航、弹层和反馈。共用业务含义与数据，根据当前端重新选择表达。
- 可按用户品牌调整 token；字号、密度、容器、圆角也需随语义适配，不能只换主色。
- 参考仓库与实际可分发内容分开判断。采用第三方代码或素材时读取[来源与许可记录](../THIRD_PARTY_NOTICES.md)，核实对应版本与声明；不把参考仓库中的 Skill 或 HIG 镜像自动打包到项目。当前 Apple 模板继续依据官方文档自行表述与实现。

## 组件控件选择

按 [design-spec.md](../design-spec.md) 共同规则中的组件选型表及行为契约，将场景映射到当前框架、版本和目标端支持的组件。复杂控件优先复用成熟实现；不要把“单 HTML”误解为“只能手写原生控件”，也不要因选定 Apple 风格而引入第三方 Skill 或假设存在统一的 Apple Web 组件 API。保持已确认技术与交付约束，按需加载和构建依赖。

需要查看真实控件或组合方式时，读[组件库与复用](component-library.md)，再定位目录中的对应场景和源码。已有工程的组件、主题及版本优先；内置 Ant Design 库是可选参考，不要求 Vue、TDesign 或其他项目迁移到 React。

## 共同质量要求

语义结构和键盘操作清楚；交互控件有可读标签和焦点；状态不只靠颜色区分。页面在目标视口可用，长文字、缩放和空态不破坏布局。尊重减少动态效果设置。

弹层明确标题、作用范围和关闭/取消语义；打开后聚焦，关闭后恢复触发位置。必要时提示未保存变更，不能以一律点击遮罩关闭代替业务判断。

桌面端处理好导航、页面头部、筛选和数据区的空间；移动端重新安排内容优先级、触控区、安全区与键盘遮挡。布局骨架由任务决定，模板示例不是所有页面的固定容器。
