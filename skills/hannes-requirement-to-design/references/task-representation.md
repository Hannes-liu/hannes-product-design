# 从用户任务选择信息表达

先明确用户必须判断什么，再选信息表达和交互控件。现有模板和控件目录提供实现材料，不能代替这一步。下表是自编选择建议，不是某个组件库的官方规范，也不是所有页面都要增加图表。

| 用户需要作出的判断 | 优先考虑的表达 | 不宜仅依赖的表达 |
| --- | --- | --- |
| 在多个资源之间比较某段时间的占用，找到足够长的空闲窗口 | 资源 × 时间占用图，并提供明确的空闲候选与选择入口 | 只有“我的记录”表格，要求逐条推算空闲 |
| 查看本人历史、按属性查找记录或批量处理 | 可筛选列表／表格，明确状态与操作 | 仅有时间图，缺少取消历史或条件查找 |
| 判断某个对象当前状态和下一步 | 状态摘要、证据、可执行动作；需要时附历史时间线 | 用历史时间线代替当前状态或可用性 |
| 比较总量、趋势、分布或异常 | 对应分析图表，标明口径及下钻 | 只放指标卡，或用装饰图表代替行动信息 |
| 判断地点、空间覆盖或邻近关系 | 地图／平面图加可访问的列表与定位 | 无关地图；仅地址文本却要求判断空间关系 |

表达方式可以互补。页面设计说明要解释“用户需要判断什么、凭哪些信息判断、如何行动”，不只记录表格／抽屉／弹窗名称。

## 资源与时间占用

适用：资源预约、排班、设备使用等任务，主要判断依赖资源、开始／结束和可用时长。查单条记录或只挑日期的任务不强制时间网格。时间线是时间表达的泛称；项目排期甘特还涉及任务进度与依赖，不能直接当作预约占用控件。

- 资源为行、统一时间为列，块的位置和宽度与实际区间对应；明确日期、时区、查看范围与粒度。不同资源可同时使用，首尾相接不等于重叠。
- 分别表达可预约、本人占用、其他占用、未开放、已过去及未知状态，只呈现实际存在的状态；未知或未开放不能因留白变成可预约。不靠颜色区分。
- 点击／键盘选择可用区间后带入资源与完整时间；占用块提供权限允许的信息，本人详情与取消继续遵守同一规则。拖选、拖动改期或合并时段仅在业务支持且明确要求时提供。
- 时长／资源筛选不应隐藏冲突事实；若有状态筛选，只能突出匹配项，不能把不匹配的占用变成空闲。记录查询与占用筛选应注明范围。
- 占用图、可用候选、记录和统计从同一业务记录推导。提交重新校验冲突；取消保留历史并释放占用。前端演示不代表真实并发控制。
- 大范围按需要横向滚动、缩放或分页；保持资源标签与时间标尺可理解。提供键盘入口、完整时段文字和可用候选，不能只靠悬浮提示或拖拽。数据量大时评估渲染成本，不把本例小数据效果当成性能结论。
- 优先复用目标项目已有日程／资源调度组件；按需评估扩展库的实际资源视图、键盘、时区、许可与离线打包能力。日期选择器只选时间，事件历史 Timeline 只叙事，组件名称中有“时间”不等于支持资源占用。本包真实 Ant Design 目录尚无此复合控件，自制案例不是新增官方组件。

可定位知识条目：`PAT-SCHEDULE`，详见[设计知识](design-knowledge.json)。[预约案例](examples/reservation.md)是预设时段的一种实现，不作为任意时长预约的通用规则。

## 在实现前验证表达是否足够

先写一项不依赖按钮名称的任务，例如：“在指定日期比较资源，找出满足所需时长且无冲突的时段，然后预约。”在初始视图检查资源、时间、可用性是否可见，有没有把未开放当空闲，能否直接进入行动；再验证创建与取消后的表达是否同步。

将任务结果与技术回归分开记录。界面能提交、没有报错，不能证明选用的信息表达支持任务。自动操作验证可证明指定路径，不能代替真实用户的发现性与理解测试。修改后保留反例：不满足时长、他人占用、未开放、查不到空闲时，用户看到了什么、如何恢复。
